# Agent notes

How an agent works on this mod. The README says what it is and how to build it.

## Layout

- `src/lib.rs` — entry points, keys (`input`), the settings page (`ui`, kept with `storage`), the chase camera,
  the rumble (`render.shake`), `/swingmode`.
- `src/spidey.rs` — the web mode: swing, zip, wall run, parkour, poses.
- `src/sense.rs` — the rays asked of the game each tick and how their hits are read. The game casts them a tick
  later, so the layout `ask` sends and the one `read` expects must stay in step.
- `tools/` — `run_take.sh` records a take, `front.sh` brings the game window forward. `HORIZON=` points them at a
  Horizon checkout (default: beside this repo).
- `native/` — the native mod: `hmod/` (the shipped `.hmod` project) and `mixins/spider_man/` are generated by
  `native/tools/release.sh` and `native/tools/hmod.py`, never edited by hand; the hooks' source is
  `native/dev/mixins/spidey-socket/`, the mod crate's `native/hmod-src/lib.rs`; `native/README.md` has the loop.
- Local only, git-ignored: `docs/DECISIONS.md` (every decision with who made it: read it before changing a
  mechanic, add a row for each new one), `docs/video-spec.md` (reference notes), `ref/` (reference footage).

## Building and running

- The native mod is what ships (Horizon's registry, Mods > Add from GitHub), as the `.hmod` project `native/hmod/`.
  Its hooks' source is `native/dev/mixins/spidey-socket/` and its crate's `native/hmod-src/lib.rs`;
  `native/tools/release.sh --generate-only` then `native/tools/hmod.py` regenerate it from them and `src/`, and the
  launcher builds it (`native/README.md` § Build). Never edit the generated files.
- Development: the live-reload loop (`native/tools/dev-build.sh`, `watch.sh`, a dev client with `HORIZON_DEV_PLUG`)
  still runs on the earlier Nightly its pins name. After changing the hooks, regenerate `native/hmod/` and play
  the launcher's build.
- The `.hmod` needs no Horizon checkout: the launcher fetches the prebuilt game and its mod tools for the pinned
  build. The live-reload loop still expects Horizon (`../horizon`) and horizon-mixins (`../horizon-mixins`) beside
  this repository; `HORIZON_TARGET=<dir>` reuses a warm Cargo target there.
- A new version, or a move to a newer Horizon Nightly: `native/README.md` § Release a version and § Move to a newer
  Horizon. A release is a GitHub release with the `.hmod`, then the registry form adds the version (entries are pinned by SHA-256).
- `native/` clippy covers only its own crates (`-p horizon-dev-reload --features host -p horizon-mod-sdk`).
- The WebAssembly build (0.1.0, Horizon's unmerged `motion` branch) is history: README § WebAssembly build.

## Testing

- Only in test worlds (a city map, a flat test ground), never in a personal survival world. If the game is open
  somewhere else, close it and relaunch in a test world.
- After every launch press F5 once: checks and screenshots are taken in third person.
- Test from known spots (a swing take and a wall run up a tower, kept with the test world), not by probing the map.
- Test in a copy of a test world: a newer Horizon may upgrade the save.
- Drive the game with `horizon-ctl key/look/chat/screenshot` (the one built with the client: `horizon-ctl` beside it). The mod's commands go through `chat`
  (`/swingmode debug`); `horizon-ctl command` goes straight to the server and the mod never sees it.
- Before driving the game, check nobody is playing: `horizon-ctl events` shows screens opened by someone else.
- After any pose change: `/swingmode debug` shows `posed 0` once standing, or the game's own animations stay off.
- A feel change is judged against the reference footage and by the person playing, not by numbers alone.

## Rules

- Pull requests only (CONTRIBUTING.md). Nothing is pushed or published without the maintainer's go.
- Public repo: no personal details, private paths or quotes in code, commits or docs. Comments say what and why
  in neutral terms.
- No code, models or animations from other mods or games; watch references, write our own.
- Before any model, texture or pose: `docs/model-style.md` (the style rules and how a model is checked in the game).
- Nothing that changes what a server sees beyond the `motion` capability's own rules.

# Native mod

The same mod as a native Horizon mod: [horizon-mixins](https://github.com/horizon-rust/horizon-mixins) bundles
whose hooks are compiled into Horizon itself, so it builds on an unmodified Horizon. The mod's logic is `src/`,
unchanged; this folder holds the game-side hooks and the tooling around them.

| Path | What |
|---|---|
| `mixins/spider-man/` | **The shipped bundle**, pinned to Horizon v0.2.96 (`compatibility.json`). Generated by `tools/release.sh`: don't edit it by hand |
| `dev/mixins/spidey-socket/` | The game-side hooks, the source the bundle is generated from (`socket.rs` + helpers + manifest) |
| `dev-reload/` | Development only: the "socket" the dev game loads the mod through, reloaded when rebuilt; `abi.rs` is the data the hooks and the mod exchange each tick |
| `sdk/` | The mod SDK's surface (`horizon_mod_sdk`) served from that data, so `src/` builds unchanged |
| `plug/` | `src/` built as the library the dev game loads |
| `tools/` | `release.sh`, `release.py`, `dev-build.sh`, `socket-commit.sh`, `watch.sh`, `horizon.py` (staging, adapted from horizon-native-mod-template) |

## Hooks

| Hook | Horizon function | Does |
|---|---|---|
| HEAD | `game::remote::Game::tick_remote` | each tick: rays, keys, the player to the mod; velocity, fall reset, pose, camera, shake, wind, chat lines back |
| HEAD + RETURN | `game::remote::Game::remote_send_state` | while the mod forgets the fall, your own world's server hears you as on the ground (never another server) |
| cancellable HEAD | `game::chat::Game::handle_chat_input`, `game::remote::Game::send_chat` | `/swingmode …` goes to the mod |
| HEAD | `game::leads::Game::leash_geometry` | the web strands |
| cancellable HEAD | `game::perspective::Game::player_model_geometry` | the posed player model (third person) |
| cancellable HEAD | `game::perspective::Game::camera_view` | chase and fixed camera, shake |
| cancellable HEAD (dev only) | `camera::view_matrix` | the wall-as-floor roll |

The mod acts only in your own world (single player, or a LAN world you host).

## Differences from the WebAssembly version

- No wall-as-floor roll in the shipped bundle: the turned view needs state shared between Horizon's game and
  its library crate, which a native bundle can't add. The dev build has it.
- While posed, the player model is drawn without armour, the held item or elytra.
- Keys are fixed (R web, Z zip), no Controls rows; no settings page; the mode help shows in chat, not a HUD
  panel. The settings file is `mod-storage/spider-man/` in the game's folder.

## Build the shipped mod

Beside this repository: a Horizon clone containing the pinned commit and
[horizon-mixins](https://github.com/horizon-rust/horizon-mixins) at the revision in `compatibility.json`.
Rust 1.95 (from `rust-toolchain.toml`), Python 3.12 via [uv](https://docs.astral.sh/uv/).

```sh
native/tools/release.sh                 # regenerate mixins/spider-man/, stage and build
native/tools/release.sh --generate-only # regenerate only
```

The client is printed at the end; run it with your prepared resources (`--resources`). With the Horizon launcher,
a native bundle is built by `horizon-launcher native-build` (off by default, it asks you to read the code and
pass `--trust-native-code`); that path has not been tried with this mod yet.

## Develop with live reload

```sh
native/tools/socket-commit.sh   # once per Horizon pin: a local Horizon commit with the socket crate
native/tools/dev-build.sh       # the dev client (about 2–3 minutes; sound on)
native/tools/watch.sh           # leave running: rebuilds the plug when src/ changes
HORIZON_DEV_PLUG=native/target/debug/libspider_man_plug.dylib  # then start the dev client with this set
```

Edit `src/` (a number in `spidey.rs`, a pose), save: the running game uses it within about a second. A change to
the hooks or to `dev-reload/abi.rs` needs `dev-build.sh` and a restart; a change to the socket crate also needs
`socket-commit.sh`. The mod's state starts over on each reload (a swing in progress drops).

`HORIZON_TARGET=<dir>` reuses a Cargo target directory between builds (a Horizon build is several GB).
